# s18c - RAM Reduction for kind

> **Tag:** `s18c`
> Goal: cut memory usage so the kind cluster runs comfortably on a 16 GB host without making Windows unusable. Before these changes, WSL consumed ~7.7 GB (the default 50% of host RAM) and the cluster ran multiple replicas of every workload. Starting `cloud-provider-kind` on top of that pushed the system past usable limits.

---

## Problem

| Component | Before | RAM cost |
| --- | --- | --- |
| WSL default allocation | ~7.7 GB (50% of 16 GB host) | leaves only ~8 GB for Windows, VS Code, browser, Claude Code |
| kind nodes | 1 control-plane + 2 workers | ~450-500 MB for node overhead alone |
| App replicas (frontend, notify-api, users-api) | 2 each | ~50-100 MB per extra replica |
| PostgreSQL (CNPG) | 2 instances (primary + standby) | ~100-200 MB for the standby |
| PgBouncer pooler | 2 instances | ~20-30 MB for the extra instance |
| cloud-provider-kind | 1 container per LoadBalancer Service | ~25 MB each, but the real cost is that it tips an already-full system over the edge |

Total overhead from duplicated replicas and the extra worker node: **~400-800 MB** inside WSL, on top of a WSL allocation that was already too large for the host.

---

## Changes

### 1. Cap WSL memory (`~/.wslconfig`)

Created `C:\Users\mabhi\.wslconfig`:

```ini
[wsl2]
memory=6GB
swap=2GB
```

### 2. Remove second kind worker node

**File:** `infra/kind-config.yaml`

Commented out the second `role: worker` entry. One control-plane + one worker is sufficient for all current stages. Uncomment if you need multi-node scheduling (anti-affinity, topology spread).

### 3. Reduce application replicas to 1

| File | Field | Before | After |
| --- | --- | --- | --- |
| `k8s/frontend/deployment.yaml` | `replicas` | 2 | 1 |
| `k8s/notify-api/deployment.yaml` | `replicas` | 2 | 1 |
| `helm/frontend/values.yaml` | `replicaCount` | 2 | 1 |
| `helm/notify-api/values.yaml` | `replicaCount` | 2 | 1 |
| `helm/users-api/values.yaml` | `replicaCount` | 2 | 1 |
| `helm/users-api/values.yaml` | `hpa.minReplicas` | 2 | 1 |
| `k8s/users-api/hpa.yaml` | `minReplicas` | 2 | 1 |

### 4. Reduce PostgreSQL and PgBouncer instances to 1

| File | Field | Before | After |
| --- | --- | --- | --- |
| `k8s/postgres/cluster.yaml` | `instances` | 2 | 1 |
| `k8s/postgres/pooler.yaml` | `instances` | 2 | 1 |
| `k8s/postgres-migration/cluster-basebackup.yaml` | `instances` | 2 | 1 |
| `k8s/postgres-migration/cluster-initdb.yaml` | `instances` | 2 | 1 |
| `k8s/postgres-migration/cluster-recovery.yaml` | `instances` | 2 | 1 |

## Reverting

Every change has a comment explaining how to revert. Search for "Reduced to save RAM" (or "save RAM") across the repo to find all of them. To restore full HA:

1. Set `.wslconfig` memory back to `8GB` (or remove the file for the default).
2. Uncomment the second worker node in `infra/kind-config.yaml`.
3. Set all `replicas`/`replicaCount`/`instances` back to `2`.
4. Recreate the cluster: `kind delete cluster --name demo && kind create cluster --config infra/kind-config.yaml`.

## Port forwards

Without `cloud-provider-kind` (or when LoadBalancer Services show `<pending>`), use `kubectl port-forward` to reach cluster services from your host. Services behind an Ingress (demo.local, grafana.demo.local, argo.demo.local) don't need port-forwarding as long as the ingress-nginx controller is reachable via `extraPortMappings`.

### Application

```bash
# App (via Ingress on demo.local, no port-forward needed if extraPortMappings is set)
# Fallback if Ingress is not working:
kubectl port-forward svc/frontend 8080:80                          # http://localhost:8080
kubectl port-forward svc/users-api 3000:80                         # http://localhost:3000/api
kubectl port-forward svc/notify-api-grpc 50051:50051               # gRPC on localhost:50051
```

### Database

```bash
# PostgreSQL primary (via CNPG)
kubectl port-forward svc/postgres-rw 5432:5432                     # psql -h 127.0.0.1 -U appuser -d appdb

# PgBouncer pooler
kubectl port-forward svc/postgres-pooler-rw 6432:5432              # psql -h 127.0.0.1 -p 6432 -U appuser -d appdb
```

### Observability (LGTM stack, namespace: lgtm)

```bash
# Grafana (has Ingress at grafana.demo.local; port-forward as fallback)
kubectl -n lgtm port-forward svc/kube-prometheus-grafana 3000:80                          # http://localhost:3000  (admin/admin)

# Prometheus
kubectl -n lgtm port-forward svc/kube-prometheus-kube-prome-prometheus 9090:9090          # http://localhost:9090

# Alertmanager
kubectl -n lgtm port-forward svc/kube-prometheus-kube-prome-alertmanager 9093:9093        # http://localhost:9093

# Loki (query frontend)
kubectl -n lgtm port-forward svc/loki-gateway 3100:80                                     # http://localhost:3100

# Tempo (query frontend)
kubectl -n lgtm port-forward svc/tempo 3200:3200                                          # http://localhost:3200
```

### GitOps

```bash
# ArgoCD (has Ingress at argo.demo.local; port-forward as fallback)
kubectl -n argocd port-forward svc/argocd-server 8443:443                                 # https://localhost:8443

# Get the admin password
kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath='{.data.password}' | base64 -d

# Open https://localhost:8443 in your browser, login: admin / <password from above>
```

### Autoscaling

```bash
# KEDA HTTP Add-on interceptor admin (metrics/queue depth)
kubectl -n keda port-forward svc/keda-add-ons-http-interceptor-admin 9090:9090            # http://localhost:9090
```

### Ingress controller (if extraPortMappings is not set)

```bash
kubectl -n ingress-nginx port-forward svc/ingress-nginx-controller 8080:80 8443:443       # http://localhost:8080
```

### Notes

- Port-forward sessions die with the terminal. Run them in separate tabs or background them with `&`.
- If a local port conflicts (e.g., Prometheus and KEDA interceptor both default to 9090), change the local side: `kubectl port-forward svc/X LOCAL_PORT:REMOTE_PORT`.
- After ArgoCD adoption (s18b), Helm release names changed. The service names above reflect the ArgoCD-managed names (e.g., `kube-prometheus-*` not `prom-*`).
