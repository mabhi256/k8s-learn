# s18a - Helm Charts for notify-api and frontend

> **Tag:** `s18a`
> Goal: migrate notify-api and frontend from raw `k8s/` manifests to Helm charts, matching the users-api chart structure. This is prep for s18b (ArgoCD), which requires a Helm source for every app workload it manages.

Up to this point, users-api is the only workload managed by Helm. notify-api and frontend are still deployed with `kubectl apply -f k8s/<app>/`. That works, but it makes them second-class citizens: no templated values, no `helm upgrade` rollbacks, and ArgoCD can't manage them as Helm sources. This stage brings all three app workloads under the same Helm model.

---

## What changed

Each new chart lives under `helm/<app>/` and contains five templates mirroring users-api: deployment, service, configmap, serviceaccount, and servicemonitor. Istio, HPA, VPA, and KEDA templates are excluded: those arrive in later stages.

### notify-api (`helm/notify-api/`)

- **Two service ports**: gRPC (50051) and metrics (9091), defined as a list in `values.yaml` under `service.ports[]`.
- **tcpSocket probes** on the gRPC port (not httpGet, since gRPC has no default HTTP health endpoint).
- **ServiceMonitor enabled** by default, targeting the `metrics` port with the same `version` relabeling as users-api.
- **ConfigMap** carries `LOG_LEVEL` and OpenTelemetry env vars.

### frontend (`helm/frontend/`)

- **Single HTTP port** (80), using the same `service.port` / `service.targetPort` pattern as users-api.
- **httpGet probes** on `/` (nginx serves the index).
- **`env: {}`** in values.yaml: the configmap template exists but `envFrom` is conditionally skipped when env is empty.
- **ServiceMonitor disabled** by default (nginx doesn't expose `/metrics`).

### Label selector change

The raw manifests used `app: <name>` as the pod selector. The Helm charts use the standard `app.kubernetes.io/name` + `app.kubernetes.io/instance` labels. Since Deployment selectors are immutable, migrating requires deleting the old Deployment before installing the Helm release. The `app: <name>` label is still present on pods (for compatibility with dashboards and network policies), but it's no longer a selector.

## Commands

```bash
# 1. Delete old raw-manifest resources
kubectl delete -f k8s/notify-api/
kubectl delete -f k8s/frontend/

# 2. Install via Helm
helm install notify-api helm/notify-api/
helm install frontend helm/frontend/

# 3. Verify
kubectl get pods -l app.kubernetes.io/name=notify-api
kubectl get pods -l app.kubernetes.io/name=frontend
kubectl get svc notify-api frontend
kubectl get servicemonitor -n lgtm notify-api
```
